# MilkTeaPet 架构说明

## 1. 工程形态

MilkTeaPet 使用标准 Xcode macOS App 工程，最低支持 macOS 13。根目录的 `Package.swift` 继续作为命令行构建和模块测试入口，与 Xcode 工程共享同一套源文件。

工程包含以下 Targets：

- `MilkTeaPet`：应用入口、SwiftUI 页面、AppKit 窗口和应用协调。
- `MilkTeaDomain`：不依赖 SwiftUI、AppKit 和 Core Data 的业务模型、协议与纯计算。
- `MilkTeaPersistence`：UserDefaults、Core Data 及 Domain Model 映射。
- `MilkTeaPetTests`：Xcode 单元测试 Target。

## 2. 架构模式

采用 MVVM-lite + Coordinator + Repository：

```text
SwiftUI View
    ↓
Feature ViewModel / Store
    ↓
Domain Service / Repository Protocol
    ↓
Persistence Repository
    ↓
UserDefaults / Core Data
```

窗口流程独立：

```text
Feature action
    ↓
AppCoordinator
    ↓
WindowController
    ↓
NSPanel + NSHostingView
```

## 3. 模块职责

### MilkTeaDomain

- `MilkTea`、`ReminderSettings` 等业务模型。
- `SettingsRepository`、`MilkTeaRepository` 等存储协议。
- `ReminderScheduleCalculator` 等无副作用业务规则。
- 不允许导入 SwiftUI、AppKit 或 Core Data。

### MilkTeaPersistence

- `UserDefaultsSettingsRepository` 保存提醒配置和当前奶茶 ID。
- `CoreDataStack` 管理 SQLite Store、迁移选项和 Context。
- `CoreDataMilkTeaRepository` 负责奶茶数据的读取与初始数据写入。
- 不包含页面状态或窗口逻辑。

### MilkTeaPet

- `AppDependencies` 是唯一生产依赖组装入口。
- `AppCoordinator` 只协调窗口和跨 Feature 流程。
- `WindowController` 管理 NSPanel 生命周期、位置和 SwiftUI 承载。
- `ViewModel` 负责页面输入、校验和调用 Repository。
- `View` 只负责布局、交互和展示。

## 4. 状态所有权

- App 生命周期对象由 `AppDependencies` 创建并持有。
- `ReminderScheduler`、`MilkTeaStore` 使用 `ObservableObject`，兼容 macOS 13。
- Feature 通过显式构造参数获取依赖，不依赖自定义全局单例。
- 页面内部短期状态使用 SwiftUI `@State`。
- UI 不直接读写 UserDefaults 或 Core Data。

## 5. 数据存储

- 设置：`UserDefaultsSettingsRepository`。
- 奶茶业务数据：`CoreDataMilkTeaRepository`。
- Core Data 默认 Store：Application Support 下的 `MilkTeaPet/MilkTeaPet.sqlite`；启用 App Sandbox 后由系统映射到应用容器。
- 旧版 `HH:mm` 时间继续按 `HH:mm:00` 兼容读取。
- Repository 会尝试从旧版 `MilkTeaPet` UserDefaults Suite 读取并迁移已有设置。

## 6. 开发约束

- 新 Feature 不得把业务逻辑继续加入 AppDelegate 或 WindowController。
- 不创建通用泛型 Repository；按业务实体定义清晰接口。
- NotificationCenter 只用于系统事件，不作为内部业务事件总线。
- 新增日期、统计和存储逻辑时优先放入 Domain，并补单元测试。
- 新增窗口统一由 AppCoordinator 和对应 WindowController 管理。
