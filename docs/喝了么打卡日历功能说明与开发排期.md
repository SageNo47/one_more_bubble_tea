# “喝了么”打卡日历功能说明与开发排期

> 文档状态：开发前方案  
> 编写日期：2026-09-03  
> 适用版本：MilkTeaPet 下一功能版本  
> 前置条件：现有架构与功能回归测试通过，记录窗口和“+1”动效视觉稿确认

## 1. 功能目标

“喝了么”用于记录用户每天喝奶茶的杯数，并通过日历查看每日记录以及周、月统计。记录既可以由提醒气泡中的“来一杯”自动产生，也可以在记录窗口中手动新增或删除。

本期目标：

- 让“来一杯”从单纯关闭气泡变成一次真实打卡。
- 提供独立的日历记录窗口。
- 支持同一天记录多杯奶茶。
- 支持按单杯新增和删除。
- 展示本周和当前浏览月份的奶茶杯数。
- 所有记录保存在本机，退出并重新启动后仍然存在。
- 保持现有宠物、设置和提醒行为稳定。

## 2. 功能范围

### 2.1 提醒气泡打卡

用户点击“来一杯”后：

1. 按用户当前本地日期创建一条奶茶记录。
2. 保存期间阻止按钮重复触发，避免一次点击产生多条记录。
3. 保存成功后关闭提醒气泡。
4. 在宠物图案上方显示一次“+1”动效。
5. 动效播放结束后自动消失，不影响宠物拖动和右键操作。

保存失败时：

- 不显示“+1”。
- 不将失败记录加入统计。
- 提醒气泡保留或展示轻量错误反馈，允许用户重试或关闭。

“今天不喝”仍然只关闭提醒，不创建饮用或跳过记录。

### 2.2 记录入口

宠物右键菜单调整为：

```text
记录
设置
────────
关闭
```

- 点击“记录”打开独立的“喝了么”窗口。
- 单击宠物同样打开“喝了么”窗口。
- 窗口已经打开时，只将现有窗口置前，不重复创建。
- 记录窗口打开后可独立移动和调节大小，不跟随宠物位置。

### 2.3 打卡日历

记录窗口初版提供：

- 按月查看日历。
- 切换上一个月和下一个月。
- 返回当前月份。
- 每个日期显示当天杯数；没有记录的日期不显示杯数。
- 选择某个日期查看当天记录。
- 对选中日期增加一杯。
- 一天可以增加多杯，每杯保存为独立记录。
- 按单条记录删除，删除后立即更新日历和统计。
- 不允许为未来日期新增记录。

### 2.4 统计规则

- 一周按周一至周日计算。
- “本周”显示当前自然周的总杯数。
- 月统计显示当前正在浏览月份的总杯数；浏览本月时文案为“本月”，浏览历史月份时可显示对应月份或“该月”。
- 一杯对应一条记录，统计结果由记录实时计算，不单独持久化汇总值。
- 删除记录后，周统计、月统计和日期杯数同步减少。

## 3. 本期不包含

- 奶茶品牌、口味、甜度、冰量和备注。
- 单杯价格和消费金额统计。
- 连续打卡、目标、成就或排行榜。
- “今天不喝”的跳过次数统计。
- 一键清空某一天或全部历史数据。
- 数据导入、导出和云同步。
- 编辑已有记录的日期或创建时间。
- macOS 系统通知和应用退出后的提醒。

上述能力可以在基础记录模型稳定后继续扩展。

## 4. 数据设计

### 4.1 Domain Model

每杯奶茶使用一条独立记录：

```text
DrinkRecord
├── id: UUID
├── day: LocalDay
├── createdAt: Date
├── milkTeaID: String?
└── source: reminder | manual
```

`LocalDay` 使用 `year/month/day` 表示用户打卡时选择的自然日。日历统计以 `LocalDay` 为准，避免用户切换时区后，深夜记录意外移动到前一天或后一天。

字段说明：

| 字段 | 说明 |
| --- | --- |
| `id` | 单条记录的稳定唯一标识，用于精确删除 |
| `day` | 记录所属的本地自然日 |
| `createdAt` | 记录实际创建时间，用于排序和问题追踪 |
| `milkTeaID` | 创建记录时当前桌面奶茶的 ID；允许为空以兼容数据变化 |
| `source` | `reminder` 表示来自提醒气泡，`manual` 表示日历手动添加 |

### 4.2 Core Data

在现有 Core Data Stack 中增加 `DrinkRecordEntity`，字段与 Domain Model 对应。Core Data 对象只存在于 Persistence 层，SwiftUI 和 Domain 不直接依赖 `NSManagedObject`。

数据层需要保证：

- `id` 唯一。
- 新增和删除操作保存成功后才更新页面状态。
- 查询结果按 `day`、`createdAt` 稳定排序。
- 使用内存 Store 完成 Repository 单元测试。
- 为模型版本升级保留迁移入口。

### 4.3 Repository

Domain 层增加专用接口：

```text
DrinkRecordRepository
├── fetchAll()
├── fetch(in dayRange)
├── add(record)
└── delete(id)
```

不创建通用泛型 Repository。具体实现为 `CoreDataDrinkRecordRepository`，由 `AppDependencies` 统一创建并注入。

## 5. 代码结构

遵循现有 MVVM-lite + Coordinator + Repository 架构：

```text
Sources/MilkTeaDomain/
├── Models/LocalDay.swift
├── Models/DrinkRecord.swift
├── Repositories/DrinkRecordRepository.swift
└── Services/DrinkStatisticsCalculator.swift

Sources/MilkTeaPersistence/
└── CoreData/
    ├── CoreDataStack.swift
    └── CoreDataDrinkRecordRepository.swift

Sources/MilkTeaPet/
├── Features/DrinkHistory/
│   ├── DrinkHistoryView.swift
│   ├── DrinkHistoryViewModel.swift
│   └── Components/
├── Platform/Windows/
│   ├── DrinkHistoryWindowController.swift
│   └── RecordEffectWindowController.swift
└── App/
    ├── AppCoordinator.swift
    └── AppDependencies.swift
```

职责划分：

- `DrinkHistoryView`：日历、统计和当天记录的布局与交互。
- `DrinkHistoryViewModel`：选择月份/日期、加载状态、增删命令和错误状态。
- `DrinkStatisticsCalculator`：日期区间与周/月杯数纯计算。
- `CoreDataDrinkRecordRepository`：实际数据增删查。
- `DrinkHistoryWindowController`：记录窗口生命周期。
- `RecordEffectWindowController`：透明、不可交互的“+1”动效窗口。
- `AppCoordinator`：串联提醒打卡、窗口关闭和动效展示。

## 6. 关键业务流程

### 6.1 “来一杯”

```text
点击“来一杯”
→ Reminder ViewModel 发起记录命令
→ DrinkRecordRepository 保存当天记录
→ DrinkHistory 状态刷新
→ ReminderWindowController 关闭气泡
→ RecordEffectWindowController 播放“+1”
```

只有持久化成功后才关闭气泡并播放成功动效。

### 6.2 手动新增

```text
选择日期
→ 校验不是未来日期
→ 新建 source = manual 的记录
→ Repository 保存
→ 刷新所选日期、月份和本周统计
```

### 6.3 删除

```text
选择一条记录
→ 用户确认删除或进入可撤销状态
→ Repository 按 UUID 删除
→ 刷新日历和统计
```

具体采用确认框还是短暂撤销提示，在 UI 设计阶段定稿。

## 7. UI 设计确认

已确认采用与现有设置窗口一致的低饱和米白、暖棕和圆角粗边框体系：

- 窗口使用左侧月历、右侧日期详情的双栏布局，初始尺寸为 `780 × 560 pt`，最小尺寸为 `700 × 480 pt`，支持拖拽调节大小。
- 标题为“喝了么”，右上角使用现有圆形关闭按钮。
- 日期格使用统一文字颜色，周日不单独标红；未来日期通过降低透明度表示不可新增。
- 有记录的日期以奶茶小图和数字组合显示杯数；今天和选中状态使用暖棕描边区分。
- 本周和浏览月份统计位于月历上方。
- 右侧显示选中日期、当天杯数、加一杯按钮和逐杯时间列表。
- 记录来源保留在数据层，当前 UI 不显示“来自提醒”或“手动添加”。
- 删除采用单条记录尾部垃圾桶按钮，初版直接删除并即时刷新统计。
- “+1”使用低饱和暖棕圆体，连续播放两次向上冒泡，总时长约 `1.65s`，透明窗口点击穿透并在屏幕边缘内避让。

UI 设计只影响 Presentation 和动效参数，不改变本文件定义的数据结构与业务规则。

## 8. 验收标准

### 8.1 功能验收

- 点击提醒气泡“来一杯”只新增一条当天记录。
- 快速连续点击不会产生重复记录。
- 保存成功后气泡关闭，并在宠物上方播放一次“+1”。
- 右击宠物可通过“记录”打开窗口。
- 同一天可以连续增加多杯。
- 可以精确删除其中一杯，不影响当天其他记录。
- 不能给未来日期添加记录。
- 本周和浏览月份统计正确。
- 月份切换后日期与统计正确刷新。
- 退出并重新启动后记录仍然存在。
- 添加和删除后，日历杯数与统计同步更新。

### 8.2 回归验收

- 宠物显示、拖动和悬停摇动正常。
- 单击宠物打开记录窗口。
- 设置保存与重启恢复正常。
- 提醒时间调度正常。
- 提醒气泡定位、跟随和上下方切换正常。
- “今天不喝”仍然只关闭气泡。

### 8.3 异常验收

- Core Data 保存失败时不显示虚假的成功结果。
- 数据加载失败时记录窗口显示错误状态，不崩溃。
- 删除已经不存在的记录不会破坏其他数据。
- 当前奶茶 ID 失效时仍可读取历史记录。

- “来一杯”成功与失败时的流程分支。

### 人工测试

- 日历布局和月份切换。
- 右键入口与重复打开窗口。
- “+1”动效位置和透明窗口点击穿透。
- 多显示器、屏幕顶部和底部位置。

## 11. 风险与依赖

| 风险/依赖 | 影响 | 处理方式 |
| --- | --- | --- |
| UI 方案未确认 | D4–D6 可能返工 | D1 先固定窗口、日历和动效方案 |
| 当前环境没有完整 Xcode | 无法验证 App Target、XCTest、签名与 Sandbox | 命令行持续构建；交付前在完整 Xcode 环境补跑测试 |
| Core Data Model 扩展 | 模型定义错误可能影响后续迁移 | 新增模型版本并使用内存 Store 测试，不直接覆盖已有 Store |
| 时区和日期边界 | 记录可能显示在错误日期 | 使用 `LocalDay` 作为日历归属的唯一依据 |
| 重复点击“来一杯” | 杯数重复 | 保存期间禁用操作并确保单次命令只执行一次 |
| 透明动效窗口抢占事件 | 影响宠物拖动或右键 | 动效窗口设置为不可交互并自动销毁 |
